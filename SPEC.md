# jsonloupe — Specification

**Status:** v3.4 (payload workflow) · **Created:** 2026-07-07

## 1. Problem & vision

Working with JSON daily (routing payloads, consignment bodies, prod log extracts) currently means
jsoneditoronline.org — which uploads work data to a third-party site, chokes on large documents
because it materializes the full tree in the DOM, and forgets everything when the tab closes.

JSON Workbench is a **local-first JSON viewer** with three promises:

1. **Document contents stay local.** No telemetry or document upload. The optional Ask flow is
   explicit about sending only the question and locally computed field/type schema.
2. **Lightning fast on large documents.** 50 MB paste-to-tree in ~1s, scrolling always 60fps.
3. **Inbuilt light memory.** Every document pasted is auto-saved locally (IndexedDB) and
   listed in a recents sidebar — no save button, no `data (14).json` in Downloads.

> **Update (v2.6, UI overhaul):** the "not an editor" v1 stance has softened — there is now
> an editable **code view** (CodeMirror, lazy-loaded) alongside the tree, plus light/dark
> themes and a redesigned shell (segmented Tree/Code switch, line-number tree gutter, landing
> card). The load-bearing architecture (§4) is unchanged: the worker still owns the parsed
> doc, the code view is capped (~3 MB) and falls back to the tree, and CM is a separate lazy
> chunk so cold-start stays instant. See §7 roadmap.

## 2. Non-goals (v1)

- **Not an editor.** v1 is view/inspect/copy. Node-level editing is a later concern.
  *(Superseded in v2.6: text-level editing via the code view — edit + `⌘S`/Apply re-parses
  through the worker. Inline **tree** editing is still out of scope.)*
- **No diff, no query bar.** These are the v2 headliners (see roadmap), not v1.
- **No server, no accounts, no sync.** Single machine, single browser profile.
- **No GB-scale files.** v1 targets the paste-workflow range (≤ ~100 MB). Beyond that is v3 (Tauri).

## 3. v1 feature set

| Feature | Detail |
|---|---|
| Paste-to-tree | Paste into landing textarea → auto-parse → tree. Zero clicks in the happy path. The paste event is intercepted and the text is captured off the clipboard **without inserting it into the textarea** — laying out tens of MB of text in the DOM blocks the main thread for seconds (measured: 3.4 s for 24 MB). |
| Open / drop file | Multi-file picker + drag-drop anywhere; every JSON/JSONL/text/raw-Zstd file lands in memory, the last opens. Files opened via the File System Access API (or Chrome drops) keep their **file handle** in IndexedDB — a `⟳ reload` button re-reads and decodes the file, surviving browser restarts. Reload validates before replacing the saved recent, so invalid regenerated bytes preserve the last valid body and active worker/viewer state. |
| JSONL | Newline-delimited JSON (log extracts, Kafka dumps) parses as an array automatically when plain parse fails. |
| Validation errors | Parse failures show message, line:column, and the offending line. |
| Virtualized tree | Only visible rows exist in the DOM. Expand/collapse, type-colored previews. |
| Copy path / copy value | Per-row hover actions. Path in JSONPath-ish form: `$.tasks[3].timeWindow`. |
| Search | Substring match over keys and primitive values (first 300 hits). Click a hit → ancestors auto-expand, row scrolled into view. |
| Light memory | Auto-save on successful parse, dedup by content hash. Recents sidebar: pin, rename, delete. Last 50 unpinned kept. |
| Format / minify | Copy pretty (2-space) or minified to clipboard. Code-view Format runs through the lossless worker representation so large integer and precise decimal tokens retain their digits. Download original. |
| Raw view | Read-only raw text tab (capped at 2 MB render; download for larger). Edit → re-parse round-trip via the landing textarea. |
| Structural diff | `⇆` on any recent = baseline vs the open doc. JSON equality (key order ignored by construction), ignore list of key names and `$` path prefixes, three buckets (changed / added / removed) capped at 2000 entries, every entry click-reveals into the tree. |
| Semantic side-by-side compare | The persistent **⇆ Compare** toolbar action chooses a baseline from Recents or a file and opens one synchronized, virtualized baseline / status / current grid directly; the compact structural summary is secondary. Conservative schema-free inference identity-aligns object collections only when a direct scalar key or two-key composite has high coverage, uniqueness, overlap, and type consistency; otherwise the array stays positional with a visible warning. Filters isolate changed, added/removed, reordered, and ambiguous rows while retaining their ancestor paths. The Alignment plan exposes normalized-path rules (`auto`, `identity`, `unordered`, `sequence`, `position`) plus optional identity keys. Aligned ordering is display-only and never mutates either input. The comparison tree has a hard 50,000-node cap with explicit truncation reporting; this is not the huge-file path used by the ordinary tree viewer. |
| Un-stringify | String values that look like embedded JSON get a `{…}` badge — click expands them as a real subtree (recursive). The original string stays authoritative: copy/stringify return it unchanged; the row is marked `⚯`. |
| Value hints | Integers in epoch-millis or epoch-seconds range (2001–2065) show a dimmed local-time date next to the value. |
| Filter mode | `filter` button prunes the tree to branches matching the search text (keys claim their subtree; values match leaves). Capped at 2000 matches; clearing restores a collapsed tree (expansion state is not preserved — accepted). |
| Table view | `tbl` on any array row renders it as a virtualized table: column union sampled from the first 500 items (≤40 cols), `(value)` column for primitive items, click-to-sort asc/desc, `#` shows original index. |
| Keyboard | `j/k`/arrows move selection, `→/←` expand/collapse, `Enter` toggle, `y` copy path, `c` copy value, `/` focus search. Breadcrumb bar shows the selected row's path. |
| Query engine | JSONPath subset + pipes, pure worker-side module ([src/query.ts](src/query.ts)), no eval(). Paths (`$..key`, slices, wildcards), predicates (`==`, ordering, `&&/||/!`, `contains`, `startsWith/endsWith`, `in`, guarded `=~ /re/`, explicit `present`/`missing`/`isNull`, field-vs-field), pipes (`count sum avg min max distinct group top bottom pluck`). Group accepts composite fields; top/bottom retain only the bounded requested window. Matching streams depth-first so counts/totals do not materialize the result list; numeric literals, predicates, ranking and aggregates compare/add exact decimal spellings rather than floats. Results integrate: click-reveal, filter-tree-to-matches, copy values, inline group/row rendering. |
| MCP agent host | Eight stable tools expose the worker engine over stdio. Single-question calls can pass `filePath` directly and receive a reusable `docId`; multi-step sessions load once and retain up to eight isolated document threads. Text plus structured responses are capped. Profiles auto-discover a bounded field set and report coverage/types/nulls/exact statistics/lengths; complete exports are pulled in 256 KiB chunks, limited by exact UTF-8 bytes, written to a same-directory temporary file, and atomically published without replacing an existing path unless explicitly authorized. |
| Ask in English | The Query panel translates English → query after an explicit model connection. OpenRouter OAuth with PKCE is recommended; a manual OpenRouter or Anthropic key is the advanced option. Credentials stay in `sessionStorage` by default and use `localStorage` only after **Remember on this device** is selected. **Privacy contract: only the question + a locally-computed schema (field names, types, array lengths — never values) is sent**; the query executes locally. The generated query shows as a dimmed editable line. Successful questions auto-save as chips — clicking a chip re-runs its stored query with zero API calls. Direct `$` queries bypass the model entirely. |
| Payload decode / encode | One conservative, magic-gated decoder accepts raw Zstd bytes, standard or URL-safe Base64 Zstd with optional padding, PostgreSQL `\x…` bytea, and common SQL/clipboard quote wrappers. Candidate sniffing and decompression run in the worker. Output is fatal-UTF-8 and JSON validated without parse/stringify, capped at 64 MiB decoded bytes with declared-size preflight where available, and stored with local transformation/source provenance. Paste, open/drop, reload, comparison-file baselines, Payload tools, and nested string derivation share the same decoder. The encoder accepts valid JSON only, so every payload this screen creates can make the reverse trip through the same decoder, and retains the Java convention `Base64.encodeBase64String(Zstd.compress(bytes))`. |
| Transport size inspector | Exact worker-side byte pipeline over the authoritative serialized text: JSON UTF-8, actual Zstd compression, canonical Base64 size/padding, and exact final envelope framing (`none`, JSON field, or one-placeholder template). Compression avoids constructing a throwaway Base64 string. Editable budgets choose which stage they measure and return within/near/exceeded plus exact headroom/overage; Kafka 800 KiB and Lambda 5 MiB are editable local examples, not universal claims. A selected semantic baseline can be inspected beside current with per-stage deltas, and decoded sources report captured Zstd bytes separately from recompression. |

## 4. Architecture

**Decision: the UI thread never holds the parsed document.** The parser Web Worker owns it and
serves *row slices* on demand. This is the load-bearing choice — it keeps the main thread
responsive regardless of document size, and it means the worker internals can later be replaced
by a Rust/WASM core (v2) or a Tauri native process (v3) **without touching the UI**.

```
┌────────────── main thread ──────────────┐      ┌───────── worker ─────────┐
│ VirtualTree (renders ~50 visible rows)  │ rows │ JSON.parse (native)      │
│ toolbar / search panel / recents        │◄────►│ lazy node records        │
│ IndexedDB store (raw text + metadata)   │ rpc  │ visible-row flat list    │
└─────────────────────────────────────────┘      └──────────────────────────┘
```

Key mechanics:

- **Parsing** uses native `JSON.parse` in the worker — unbeatable in-browser; the UI thread
  only ever blocks on DOM work.
- **Lazy node records.** Child nodes are materialized only on first expand. A collapsed 5M-element
  array costs one node record, not five million.
- **Visible-row model.** The worker keeps a flat array of visible node ids. Expand/collapse splices
  it; the tree asks for `rows(start, count)` and renders exactly that slice at fixed row height.
- **Semantic comparison model.** The worker parses the baseline losslessly, infers or applies an
  array-alignment plan, and owns a separate capped comparison tree. The main thread asks for slices
  of a single aligned row list, so expansion, filtering, selection, and vertical scrolling cannot
  drift between the baseline and current columns. Identity and composite tokens are type-aware;
  `"42"` does not match `42`, and lossless integer digits are preserved.
- **Memory** stores the raw text (not the parsed tree) in IndexedDB, split into `meta` and `text`
  object stores so listing recents never loads document bodies.

### Worker protocol (rpc, request/response by `reqId`)

| Request | → Response | Notes |
|---|---|---|
| `parse {text}` | `{ok, totalRows, parseMs}` or `{ok:false, error, line, column, context}` | Resets worker state; root auto-expanded. |
| `rows {start, count}` | `{rows: Row[]}` | `Row = {id, index, depth, key, type, preview, hasChildren, childCount, expanded}` |
| `toggle {id, index}` | `{totalRows}` | `index` is a hint; worker validates and falls back to search. |
| `collapseAll` | `{totalRows}` | Back to root + first level. |
| `search {query}` | `{results: [{pathText, preview, where}]}` | Worker retains result paths for reveal. |
| `reveal {index}` | `{rowIndex, totalRows}` | Expands ancestors of result `index`, returns row to scroll to. |
| `stringify {space}` | `{text}` | Pretty (2) or minified (0). |
| `nodeValue {id}` / `nodePath {id}` | `{text}` | For the copy actions. |
| `compareInit {baselineText, rules, displayMode, nodeCap}` | `{totalRows, nodeCount, summary, plans, truncated, truncation}` | Builds an isolated semantic comparison against the open document; UI currently requests aligned display with a 50,000-node cap. |
| `compareRows {start, count}` | `{rows: CompareRow[]}` | Virtualized baseline / status / current row slice. |
| `compareToggle {id, index}` | `{totalRows}` | Expands or collapses the shared aligned row. |
| `compareSetView {filter, displayMode?}` | comparison metadata | Applies a status filter or rebuilds display ordering without changing either input document. |
| `compareCollapse` / `compareClose` | `{totalRows}` / `{ok}` | Collapses the comparison or releases its worker-side state. |

### Data model (IndexedDB `json-workbench`, v1)

- `meta`: `{id, title, size, createdAt, updatedAt, pinned, hash}` — `hash` is a sampled FNV-1a
  (first/last 32 KB + length) used for paste dedup.
- `text`: `{id, text}` — raw document body.

## 5. Performance budgets

| Operation | Budget |
|---|---|
| Paste-to-tree, 50 MB | ≤ 1.5 s total, main thread never blocked > 50 ms |
| Scroll | 60 fps at any document size (DOM rows ≤ ~80) |
| Expand/collapse | ≤ 100 ms perceived |
| App load | ≤ 200 ms (no framework, tiny bundle) |

## 6. Known limits (accepted for v1)

- ~~Expanding a multi-million-element array materializes all child records at once.~~ **Fixed
  (v3.1):** chunked expansion interposes `[0 … 9999]` range rows (`CHUNK` = 10 000), so each expand
  splices at most 10 000 records; a 5 M-element array expands to ~500 chunk rows.
- Raw view renders only ≤ 2 MB; larger documents offer download instead.
- Search allocates a path array per visited node — fine to ~1M nodes, revisit with the WASM core.
- Semantic comparison currently materializes its own alignment tree and stops at 50,000 nodes.
  Truncation is reported in the UI; no claim is made that side-by-side comparison supports the
  multi-million-node scale of the lazy/chunked ordinary tree.
- One document open at a time (memory keeps others one click away).

## 7. Roadmap

- ~~v2 — compute: structural diff, filter, un-stringify, table view~~ **shipped 2026-07-08**
  (TS implementations in the worker).
- ~~v2.6 — UI overhaul: editable code view, light/dark themes, redesigned shell~~
  **shipped 2026-07-18.** Editable **code view** via CodeMirror 6 (JSON highlighting, line
  numbers, code folding, search) in `src/code.ts` — lazy-loaded on first open (separate build
  chunk) so cold-start stays instant; edits re-parse through the worker `parse` on Apply/`⌘S`,
  capped at ~3 MB with a tree fallback. **Light/dark themes** via CSS custom-property token
  sets (`src/theme.ts`, persisted, OS-preference default); the CM editor re-themes in lockstep
  via reconfigurable compartments. Shell: segmented **Tree/Code** switch, line-number **tree
  gutter**, landing card. Replaced the old read-only raw-text pane and its edit round-trip.
- ~~v2.6.1 — split view + inline tree editing~~ **shipped 2026-07-18.** **Split** mode shows
  tree + code of the same doc side by side (resizable divider, persisted); clicking a tree node
  reveals its line in the editor via a worker `stringifyLines` map (byte-identical to
  `JSON.stringify(·,2)`, so line numbers line up exactly). **Inline editing**: double-click a
  primitive leaf → edit its JSON literal → worker `setValue` mutates the parent slot in place
  (primitives only; structural edits stay in the code view; refused inside un-stringified
  subtrees). Both panes/edits reuse the single VirtualTree + CodeEditor via CSS layout, so the
  worker-owns-the-doc architecture is untouched.
- ~~v3 — fidelity + power~~ **shipped 2026-07-18.** The headline is **losslessness** (the axis
  that most separates great from good): the worker now parses via `lossless-json` with a custom
  number parser that boxes a number as a `LosslessNumber` **only when JS would lose it** (int64 > 2^53,
  high-precision decimals) — so the parsed tree isn't wrapper-bloated, and order/consignment/snowflake
  IDs survive paste→tree→code→copy→edit→download→diff exactly. Threaded through every value path
  (`isContainer`/`typeOf`/`previewOf`/`stringify`→`llStringify`/`nodeValue`/`setValue`/`serializeWithLines`/
  diff `leafEqual`/table cells/schema; query predicates and aggregates retain exact numeric semantics).
  Plus: **value lenses** (epoch→date, lat/lng `📍`, uuid/url/base64 hints), **byte-weight**
  on containers + fat string leaves (memoized `byteLen`), **copy-path trio** (JSONPath / JSON Pointer /
  JS accessor via `nodePaths`, surfaced as breadcrumb chips), **value-identity linking** (`sameValue`
  → every node with the same scalar; type-tagged so `"42"` ≠ `42`), **identity-keyed array diff**
  (`doDiff` matches by a declared key so reordered routing arrays don't report false changes), and a
  **raw-source** code-view toggle (exact original bytes). Fidelity was verified end-to-end via worker
  probes: 19-digit IDs exact in tree/code/copy/edit, self-diff = 0 changes, code bytes byte-identical.
- ~~v3.1 — resilience~~ **shipped 2026-07-18.** Four robustness features for real-world log/paste
  input. **Auto-repair** (`jsonrepair`, same josdejong family as lossless-json): malformed input —
  trailing commas, single quotes, Python `None`/`True`/`False`, truncation — is repaired and parsed
  instead of hard-failing, with parse precedence **valid JSON → JSONL → repair → fail** (on double
  failure the *original* parse error is returned; repair is gated to `{`/`[`-leading input so it
  never swallows a base64 zstd blob or valid JSONL). The stored raw text stays the user's original
  bytes; a `⚠ input repaired` badge opens the code view's raw-source toggle. int64 digits pass
  through repair untouched (syntax-only). **Document undo/redo**: worker-side command stacks
  (`setValue` inline edits + `replaceDoc` code-view Applies), `⌘/Ctrl-Z` / `⌘/Ctrl-Shift-Z` /
  `Ctrl-Y`; LosslessNumber digits restored exactly; capped at 100 commands / 64 M stored chars
  (drop-oldest); redo clears on any new edit; inert inside inputs and CodeMirror (which keeps its
  own pre-Apply history). Node ids/expansion reset on a `replaceDoc` undo (accepted). **Chunked
  expansion**: a container with more than `CHUNK` (10 000) children materializes synthetic
  `[0 … 9999]` chunk rows instead of one node per element, so a 5 M-element array expands to ~500
  records, and each chunk expands to ≤10 000; chunk rows are invisible to paths / search / copy /
  diff / serialize (those walk raw values), and reveal-by-path descends through the containing
  chunk. A chunk row carries its parent container reference, so `setValue` on a nested element
  mutates the true slot. **Worker test suite**: the `onmessage` dispatch was extracted into an
  exported pure `handle(msg)` seam (the worker glue is a guarded one-liner around it, so the module
  imports cleanly under Node/vitest); `src/worker.test.ts` drives 49 real protocol-sequence tests
  through it. Verified live at 5 M scale: 37 MB parsed in ~0.9 s → 501 rows after root expand,
  deep-element reveal `$[2345678]` in ~5 ms, self-diff = 0, `serializeWithLines` byte-identical.
  Total vitest suite: **85 green** (36 query + 49 worker).
- ~~v3.2 — feedback & polish~~ **shipped 2026-07-19.** Seven follow-ups closing v3.1's rough
  edges. **Undo-by-path**: a `setValue` command now stores the node's **path segments**, not its
  id, and re-resolves the path (through chunks, via `stepInto`) at undo/redo time — so an inline
  edit made *before* a code-view Apply survives the Apply's `replaceDoc` (which regenerates ids)
  and is still undoable; if the path no longer lands on a live leaf (shape changed — e.g. the leaf
  was un-stringified into a subtree) the command is dropped with `{did:null, reason:'gone'}` and
  the UI toasts "undo target no longer exists". **Regex search**: a `/pat/` or `/pat/i` query
  (flag subset `i` only) compiles to a `RegExp` over the *same* haystacks as a literal search (key
  names, scalar value strings); anything else — including `/usr/local` — stays a case-insensitive
  substring, so literal semantics (a `.` is a dot) are untouched; an invalid pattern returns
  `{error:'invalid regex'}` and runs no search (red hint), and the 300-hit cap applies to both.
  **Filter keeps expansion**: entering filter snapshots the pre-filter `expanded` set + visible
  rows once (repeated filter edits don't re-snapshot the derived view); clearing restores it
  exactly (ids are stable — filtering never reparses); a reparse while filtered invalidates the
  snapshot (`clearState`) and clear falls back to collapse. **Auto-diff on reload**: `⟳` holds the
  outgoing bytes and, after a successful same-doc re-parse, runs the worker `diff` against them — a
  `N changes vs previous load — view` toast opens the existing diff panel with the previous load as
  baseline (a new arbitrary-baseline entry point alongside the recents one); zero-change reloads
  just toast, no panel; `prevText` is memory-only, one level, overwritten each reload. **CSV
  export**: a worker `csv` message (RFC 4180 — comma/quote/newline quoting, doubled inner quotes,
  CRLF rows) builds from the table view (its exact first-seen column union + current sort order) or
  a query result (pluck rows / group counts; value & bare-match shapes refused); LosslessNumber
  cells emit exact digits, nested object/array fold into one `llStringify` cell, null/absent →
  empty; capped at 50 M chars (refuse, never truncate silently). Buttons on the table bar + on
  exportable query results download via Blob + anchor. **Live query preview**: the resolved query
  sits in an editable input; every edit re-runs the engine **debounced 300 ms** (a `previewToken`
  discards stale responses) and renders a styled `live preview` (count + first 50 rows) in place;
  engine errors render as an inline red hint, never a toast storm; Enter/Run commits it as today —
  **no LLM calls during preview**, engine only. **LLM transparency**: a `▸ sent to model`
  disclosure renders straight off the one `SentPayload` object `nl.ts` both sends and discloses
  (endpoint, model slug, question, schema summary, and — after the response — the raw query
  returned, plus the exact request body), so what's shown is provably what left the browser; a
  direct `$` query discloses "runs locally, nothing sent". Verified live via `__wb.call` worker
  probes + real-DOM drive: the undo boundary (setValue → Apply → ⌘Z ×2 restores the inline edit),
  `/re/i` + invalid-regex hint + literal semantics, filter snapshot/restore/invalidate, the CSV
  escaping matrix with 19-digit ids exact + the 50 M cap, the 300-hit cap, live-preview debounce +
  inline error, and the **5 M-element array driven through a real simulated `drop` event** (38.9 MB
  → chunked in ~1.4 s, deep reveal across chunks) — closing v3.1's "file flow never driven" gap.
  Total vitest suite: **113 green** (36 query + 73 worker + 4 nl).
- **v3.3 — semantic side-by-side comparison, implemented locally 2026-07-26.** The compact structural
  diff now leads into a three-column aligned workspace (baseline / status / current) backed by one
  virtualized row list. Schema-free Auto mode discovers high-confidence direct scalar or two-key
  composite identities for object collections and otherwise stays deliberately positional; it
  never silently treats primitive arrays as unordered bags. Reordered entity rows are separated
  from value changes, unresolved missing or duplicate identities remain visible as ambiguous, and type-tagged
  matching preserves lossless numeric IDs and keeps `"42"` distinct from `42`. Status filters
  retain ancestors, while the Alignment plan lets the user set normalized-path rules to `auto`,
  `identity`, `unordered`, `sequence`, or `position`. Alignment is view-only. The semantic tree is
  explicitly capped at 50,000 nodes and reports every truncated comparison instead of implying
  huge-file support. Current Vitest suite: **137 green** (including 20 semantic datasets and 4
  worker-RPC comparison flows).
- **v3.4 — payload workflow, implemented locally 2026-07-26.** Comparison is now a first-class
  toolbar action: its baseline picker accepts another Recent or a file and opens semantic
  side-by-side directly, while structural summary is computed only when requested. The payload
  codec now shares one structured decoder across paste, file/drop, reload, comparison baselines,
  the Payload tools screen, and nested string derivation. It supports raw Zstd, standard or
  URL-safe Base64, PostgreSQL bytea, and quoted SQL/clipboard cells; strong frame-magic gating,
  fatal UTF-8, exact text preservation, transformation provenance, declared-size preflight, and a
  64 MiB decoded-output cap keep guessing and allocation bounded. Candidate sniffing and
  decompression run in the worker. Raw-source reload is transactional across worker state, the
  active viewer, and IndexedDB; asynchronous opens and recent saves are generation-guarded, while
  exact source-aware dedup prevents hash candidates or derived payloads inheriting an unrelated
  file handle. The transport inspector measures worker-side JSON UTF-8, Zstd, Base64, and exact
  envelope bytes without a throwaway encoded string; during comparison it renders
  baseline/current reports and byte deltas, and distinguishes captured Zstd bytes from a fresh
  recompression. Current Vitest suite: **193 green** (payload, transport, semantic comparison,
  persistence, transactional reload, and lossless-format datasets included). A fresh real Chrome
  profile verified direct comparison, raw-Zstd import/baseline/reload, bytea, quoted and plain SQL

- **v2.5:** JSONPath predicate filters (`$.tasks[?(@.status=='PENDING')]`), array diff by
  identity key instead of position (LCS or configurable `id` field), chunked expansion for
  multi-million-element arrays, per-doc expansion-state memory. The diff/filter/query engines
  are the Rust→WASM candidates: big input, small output across the boundary, so the WASM↔JS
  marshalling tax doesn't apply.
- **v3 — scale (only if GB files become real):** same UI lifted into Tauri; Rust core mmaps the
  file, builds the index natively, serves the same slice protocol over IPC.
